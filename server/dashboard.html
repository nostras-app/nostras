NOSTRAS Node waitlist

Counts unique relay WebSocket connections to this NOSTRAS node — not unique visitors. A reload, a reconnect after a network hiccup, or the same person on multiple devices each count separately, so treat this as a volume/trend signal, not a precise headcount. Country is looked up from the connecting IP address at connection time only; the IP itself is never stored, only the resulting country code.

"DVM activity" (in the Server health panel above) only reflects DVM-kind events observed passing through this relay — it requires someone to have actually submitted a job, so silence doesn't distinguish "the DVM is down" from "nobody's asked it anything recently." The separate "DVM health" panel below it is the DVM process reporting on itself directly (uptime, memory, its own connection status to this relay), fetched over Fly's private network — a real signal, not inferred from job traffic, though it still isn't the same as a scheduled end-to-end liveness check (that's what the uptime-check GitHub Action does, on its own timer, by actually submitting a real job).
